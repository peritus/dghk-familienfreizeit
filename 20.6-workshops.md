# 20.6 — Workshops

Module id `workshops` · factory `workshops`

## 1. Purpose and boundary

Workshops records the occasion programme: time slots, the workshops offered in each,
their capacity and age bounds, who they are for, who leads them, and manual
cancellation. It does not collect preferences or assign participants; those are
[workshop rankings](20.7-workshop-rankings.md) and
[workshop assignment](20.8-workshop-assignment.md). A programme without assignment
is a valid occasion: the module alone produces a published schedule.

This document is the authoritative description of slots, workshops, audience,
leadership, and manual cancellation.

## 2. Dependencies

Requires: none. Enhances: [`room-inventory`](20.1-room-inventory.md) —
when selected, a workshop may be held in a room.

## 3. Parameters

```ts
type WorkshopsParams = {
  audience_tag: string | null        // workshop property restricting participation
  leader_tag: string | null          // person property naming a led workshop
  leaders_consume_capacity: boolean
  require_leader: boolean
}
```

| Parameter | Default | Validation |
|---|---|---|
| `audience_tag` | `null` | fills the audience role (§6) |
| `leader_tag` | `null` | fills the leadership role (§6) |
| `leaders_consume_capacity` | `false` | `true` requires `leader_tag` |
| `require_leader` | `false` | `true` requires `leader_tag` |

## 5. Events

### `SlotAdded` / `SlotUpdated`

```ts
{ slot_id: string, label: string, starts_at: string, ends_at: string, sort_key: number }
```

Folds to `label`, `starts-at`, and `ends-at`. *Invariant:* `starts_at < ends_at`.
Slots are processed in `sort_key`, then `id` order, which must be chronological.

### `WorkshopAdded` / `WorkshopUpdated`

```ts
{
  workshop_id: string,
  slot_id: string,
  title: string,
  description: string | null,
  capacity: number,
  min_capacity: number,
  min_age: number | null,
  max_age: number | null,
  room_id: string | null,
  sort_key: number
}
```

Folds to `offered-in = slot_id`, `title`, `description`, `capacity`,
`min-capacity`, `min-age`, `max-age`, and `held-in = room_id`. *Invariants:*
`0 ≤ min_capacity ≤ capacity`; `min_age ≤ max_age` when both are set; `room_id` is
null unless `room-inventory` is selected, and otherwise names a live room.

### `WorkshopCancelled`

```ts
{ workshop_id: string, reason: string }
```

Manual cancellation by an organiser. It is distinct from under-subscription
cancellation, which [workshop assignment](20.8-workshop-assignment.md) derives on
every run and reports in the trace — that is not an event, because it would
re-derive itself anyway.

### `WorkshopReinstated`

```ts
{ workshop_id: string }
```

Undoes a manual cancellation.

All workshop events are organiser-only.

```kdl
SlotAdded slot_id=slot_sat-morning label="Samstag Vormittag" starts_at="2027-05-01T08:00:00Z" ends_at="2027-05-01T10:30:00Z" sort_key=1
WorkshopAdded workshop_id=ws_toepfern slot_id=slot_sat-morning title="Töpfern" description=#null capacity=12 min_capacity=6 min_age=8 max_age=#null room_id=#null sort_key=1
LabelSet entity_id=ws_toepfern key=workshop-audience value=children strength=#null
LabelSet entity_id=per_anna key=leads-workshop value=ws_toepfern strength=#null
```

## 6. Labels and tag roles

Module-owned label keys: `label`, `starts-at`, `ends-at` on slots; `offered-in`,
`title`, `description`, `capacity`, `min-capacity`, `min-age`, `max-age`, `held-in`,
and `cancelled-reason` on workshops. All are set only by the module's events.

| Role | Parameter | Required tag shape |
|---|---|---|
| Audience | `audience_tag` | `property`, scope `workshop`, value `enumOf(…)`, cardinality exactly one, organiser-only |
| Leadership | `leader_tag` | `property`, scope `person`, value `ref('workshop')`, cardinality zero or more, organiser-only |

A workshop may have zero, one, or many leaders, and a person may lead many
workshops. Children may lead. Leadership is not participation: a leader is not
assigned to the workshop and does not consume capacity unless
`leaders_consume_capacity` is set. The audience controls who may participate; it
does not constrain who leads.

## 7. Solver input and stages

```ts
type WorkshopsInput = {
  slots: readonly { id: string, starts_at: string, ends_at: string, sort_key: number }[]
  workshops: readonly {
    id: string
    slot_id: string
    capacity: number                 // reduced by leaders when leaders_consume_capacity
    min_capacity: number
    min_age: number | null
    max_age: number | null
    audience: string | null
    leader_ids: readonly string[]    // sorted
    room_id: string | null
    sort_key: number
  }[]                                // sort: slot order, sort_key, id
}
```

Manually cancelled workshops are excluded when the solver input is built.

Stages: none of its own.

## 8. Rules and scoring

None.

## 9. Preflight checks

| Id | Severity | Fires when |
|---|---|---|
| `workshops.missing-leader` | warning | `require_leader` is set and a workshop has no leader |
| `workshops.leader-clash` | error | a person leads two workshops in one slot |
| `workshops.room-clash` | error | two workshops in overlapping slots are held in one room |
| `workshops.age-band-without-eligible` | warning | no person's age at the occasion start falls within a workshop's bounds |

## 10. Output and diff

No plan section. `world.slots` and `world.workshops` expose the programme.
`diff` reports `workshop-cancelled` and `workshop-changed` (time, room, title) for the
workshop programme report and change emails.

## 12. Tests

- Invariants on capacity, ages, and slot times, at append and replay.
- Leaders never count as participants unless `leaders_consume_capacity`.
- A room reference fails when `room-inventory` is not selected.
- Fixture contract: two slots, one children's and one adults' workshop, one child
  leader.

## 13. When not selected

No slots or workshops exist; workshop events fail replay; the workshop screen,
programme, and roster reports are absent; `workshop-rankings`,
`workshop-assignment`, and workshop links in `materials` are unavailable.
