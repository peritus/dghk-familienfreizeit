# 20.13 — Change notifications

Module id `change-notifications` · factory `changeNotifications` · version `1.0.0`

## 1. Purpose and boundary

Change notifications emails families when a plan is published: the assignment on
first publication, and only what changed on later ones. It owns the publication and
change email kinds and the choice of recipients. Email transport, `email_log`, and
the invitation and reminder emails are kernel ([deployment](13-deployment.md) §4,
[authentication](11-authentication.md)).

A family whose assignment did not change receives nothing. That is what makes
re-publication socially acceptable rather than something that trains people to
ignore the emails.

## 2. Dependencies

Requires: none. Enhances: none. It reads the change kinds of whichever assignment
modules are selected.

## 10. Output and diff

When a publication has `notify: true`, after the append succeeds:

```
previous = derive(log before the previous PlanPublished)
current  = derive(log before this PlanPublished)
changes  = diff(previous, current) filtered to change_kinds
for each family with at least one change, in family sort order:
  send a change email (or a publication email if there is no previous publication)
  write email_log
```

It is a loop over `diff`, nothing more. Sending is triggered by the organiser who
published; there are no scheduled or automatic sends.

## 11. Screens, controls, reports, and emails

| Kind | Contribution |
|---|---|
| Emails | **Publication** — the family's assignment in the body, not only behind a link, because people forward it and read it on trains. **Change** — only what changed, before and after ([family view](10-family-view.md) §4) |
| Screen | "Notify families" on publish, with the exact recipient list ([organiser view](09-organiser-view.md) §6, [UI-11](ui/11-plans-and-publishing.md)) |
| Reports | Change notice (shared) ([reports](19-reports.md) §3.1) |
| Controls | none |

## 12. Tests

- Only families with a change in `change_kinds` are emailed.
- Publishing twice with no changes sends nothing.
- Every send writes `email_log`, including failures.

## 13. When not selected

Publishing never notifies; the notify option, change notice report, and publication
and change emails are absent.
