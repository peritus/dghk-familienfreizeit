This is the local visual contract for the React application. Stories are the
executable examples; this page records the usage decisions around them.

## Universal screen composition

Every current and future screen uses `ApplicationFrame` for landmarks and width,
then `ScreenLayout`: `ScreenHeader`, screen-wide
`ActionableNotices`, workflow/status, `StatsStrip`, tertiary navigation, then content.
Optional slots collapse. Screen-wide context stays visible across local tabs.
Create actions belong to `CollectionSection` headers, including nested collections;
use the same `CollectionCreateAction` and an explicit result-oriented label at each
scope. Filters follow the collection they affect. `PrimaryNavigation`,
`SecondaryNavigation` and `TertiaryNavigation` name the three navigation levels.

## How to choose a primitive

- Use `Button` for an explicit action and give the action a result-oriented label.
- Use `Card` to group related information, not to replace page hierarchy.
- Use `Alert` for status and recovery information; include text, not only color.
- Use `AlertDialog` before destructive or consequential actions.
- Use `SegmentedControl` for a small visible choice set, not as a general select replacement.
- Use `Tag` for a quiet, borderless room property; use `Badge` for state.
- Use `StatsStrip` when the number of cells is data-driven and omit zero-value optional cells.
- Use `SuccessState` for a positive empty state; do not put it in a dashed warning container.

## Workflow progress

<Canvas of={WorkflowStepperStories.WorkshopChoice} />

Use `WorkflowStepper` to report a short ordered process such as Workshopwahl or
Unterbringung. It is status, not navigation: its current step comes from the
screen's derived view and it never changes domain state itself.

## Navigation levels

Primary navigation moves between organiser-wide areas. Secondary navigation
moves between routes in one area. Use `TertiaryNavigation` only for sibling
views within the active context, using local state or existing URLs. Filters
belong to the affected collection, below its heading. Person/entity selectors do
not introduce another navigation level.

## Shared collection patterns

Generic fields, notices, lists, rows, table frames, entity pickers, states and print
composition live in `shared/ui`. Use their semantic APIs before writing another
layout wrapper. Domain modules retain specialised cells and their event handlers.

## Printing every screen

Use the browser print dialog on every screen. `ApplicationFrame` provides event
identity and the shared `PrintFooter`; specialised reports reuse that footer and
extend the paper layout. Printing hides navigation/actions/dialog overlays, shows
current field values and selected view/filter context, and forces white paper.
Use portrait by default; matrices and whole-programme grids use landscape.
Reserve footer space, repeat table headers and test multi-page output. No
application print or export button is added.

## Organiser presentation

The application bar uses the short event title, the configured organisation and the real
logo. Folder tabs form its bottom edge; secondary navigation occupies the full width band
below it. Route-backed tertiary views are native links with `aria-current`; local choices
retain tab keyboard navigation. Active horizontal navigation stays in view.

Use the 12/14/16/18/20/24/30px type scale, 2px outlines and 5px corners. Primary action orange
is distinct from the soft context colour and dashed cream advisory surfaces. Pressable
controls have a 4px shadow, a 2px hover press and a full active press; reduced motion keeps
the control stationary. The established save-status control is an explicit exception and
keeps its presentation and behaviour.

Metrics use separate bordered tiles, two columns on phones and up to four on desktop.
A filter metric uses a native button with `aria-pressed` and shares the collection checkbox
state. Collection rows can supply a right metric column; identity, muted metadata and
record advisories stay in the text column. Avoid default-state badges.

Workflow disclosure starts collapsed at every width. Its preference is scoped to the
organiser and page. Expanded content shows the next action; a completed workflow shows the
completion date supplied by its module, with reopening outside the card. Paper expands
all steps and hides controls. Disclosure does not change a domain phase.

The workshop examples use every ranked wish for demand and include an all-audience workshop
in both audience filters. Oversubscription is information. Age/audience and missing-leader
advisories allow saving. Festlegen reviews those advisories inline, without duplicating the
result shown in the main views. Acknowledgement belongs to one finalisation attempt.
